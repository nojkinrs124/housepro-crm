# Spec Kit в HousePro CRM

GitHub Spec Kit — инструмент spec-driven development: фича сначала описывается
спецификацией, потом планом и списком задач, и только потом пишется код.
Поставлен 03.09.2026, версия CLI 1.0.4, интеграция `claude`, скрипты `sh`.

## Когда применять

Spec Kit — для **новой функциональности среднего и крупного размера**: раздел CRM,
новая сущность, переработка сценария. Для правки текста, одной кнопки или починки
бага он избыточен — там обычный рабочий цикл и skills `housepro-*`.

Spec Kit **не заменяет** правила проекта: `CLAUDE.md`, skills и хуки продолжают
действовать. Конституция (`.specify/memory/constitution.md`) — это те же правила
в форме, которую Spec Kit сверяет на каждом плане.

## Цикл

| Шаг | Команда | Что получается |
|---|---|---|
| 1. Спецификация | `/speckit-specify <описание фичи>` | `specs/NNN-имя/spec.md` — что и зачем, без техники |
| 2. План | `/speckit-plan` | `plan.md` + `research.md`, `data-model.md`, `contracts/` — со сверкой по конституции |
| 3. Задачи | `/speckit-tasks` | `tasks.md` в порядке зависимостей |
| 4. Реализация | `/speckit-implement` | код по задачам |
| 5. Выкат | skill `housepro-release` | `npm run check`, версия, коммит, пуш |

**23.10.2026: шесть скиллов сняты** (`clarify`, `analyze`, `constitution`, `checklist`,
`converge`, `taskstoissues`) — 2286 строк, использовались один раз на `specs/001` и
не несли уникальной процедуры сверх `specify/plan/tasks/implement`. Оставлен базовый
цикл из четырёх шагов; при повторной необходимости уточнения требований или сверки
план/код — делать вручную, как обычный рабочий цикл.

## Что где лежит

```
.specify/memory/constitution.md   принципы проекта, сверяются на каждом плане
.specify/templates/               шаблоны spec / plan / tasks / checklist
.specify/scripts/bash/            скрипты: создание фичи, проверка предусловий
.specify/feature.json             указатель на текущую фичу (локальный, в .gitignore)
.claude/skills/speckit-*/         сами команды (specify/plan/tasks/implement — остальные 6 сняты 23.10.2026)
specs/NNN-имя-фичи/               артефакты фичи — коммитятся вместе с кодом
```

Нумерация фич сквозная и последовательная: `001-`, `002-`, … Git-веток Spec Kit
сам не создаёт — ветка заводится обычным способом.

## Обновление

```bash
uv tool upgrade specify-cli
specify init . --integration claude --script sh --force --non-interactive --ignore-agent-tools
```

Повторный `init` обновляет шаблоны и команды. Конституция при этом сохраняется:
CLI перезаписывает `constitution.md` только если он не тронут с шаблонного вида.
Перед обновлением всё равно стоит убедиться, что дерево чистое, — тогда любые
неожиданные правки видны в `git diff`.
