# HousePro CRM — как мы работаем

Процесс: что сделать до задачи, во время и перед пушем. Правила кода — в `CLAUDE.md`,
процедуры — в skills `housepro-*`, приоритеты — в `docs/IMPROVEMENTS.md`,
хроника прошлых сессий — в `docs/JOURNAL.md`.

Файл короткий намеренно: раньше здесь же лежало 27 KB истории сессий, и из-за этого
не читалась ни история, ни сам процесс.

---

## Контекст (зафиксировано 20.07.2026)

- **Контур:** внутренний, живых клиентов нет, единственный пользователь — Руслан.
- **Команда:** Руслан + Claude, надолго. Поэтому здесь **нет** CODEOWNERS, PR-темплейтов, branch protection, husky/lint-staged — это процесс под команду, которой не существует. Не предлагать их снова, пока команда реально не вырастет.
- **Приоритет сейчас:** техдолг из аудита 20.07.2026, в фиксированном порядке (см. ниже), затем — фичи (Telegram-бот, публичный API, Stripe live keys).
- **Философия тестов:** не покрытие, а регресс-защита. Не гнаться за метрикой — важно, чтобы новая фича не тихо ломала старую.

## Перед началом любой задачи

- [ ] `CLAUDE.md` грузится сам; процедуры — по skills `housepro-*`, не по памяти.
- [ ] Работаем в текущем чекауте. Клонировать репозиторий заново не нужно.
- [ ] Если задача трогает схему БД — свериться с актуальным списком таблиц через Supabase MCP (`list_tables`), а не с памятью/документацией, которые могут отставать.
- [ ] Если задача похожа на новую фичу/значимое решение — прогнать через `grill-me`, а не додумывать самому.

## Во время разработки

- [ ] Новая форма → только через `ServerActionForm`, без `formAction()`-антипаттерна.
- [ ] Новый Server Component → ноль event handlers, ноль `useState`/`useEffect`.
- [ ] Новый Supabase-клиент в API route → через `getSupabaseAdmin()` лениво внутри хендлера, с `no-store` fetch-конфигом. Не копировать инстанциацию в 23-й файл — если паттерн повторяется в очередной раз, вынести в общий `withOrgAuth()`/`withApiKeyAuth()`.
- [ ] Новый GET route с данными по org → обязательно `export const dynamic = 'force-dynamic'`.
- [ ] Новая RLS-политика → без сабквери к той же таблице (используй `get_user_org_id()`), обёрнута в `DO $$ BEGIN IF NOT EXISTS ... END $$`.
- [ ] Правишь файл >300 строк — выносишь логику в `features/*/services`, не оставляешь как есть «раз уж всё равно тут».
- [ ] Если меняешь денежный/юридический поток (payments, contracts, billing) — обязательно тест на этот поток, даже если остальное без тестов.

## Перед пушем (обязательно, без исключений)

> Полная процедура — skill `housepro-release`. Пуш без зелёной проверки блокируется
> хуком `.claude/hooks/guard-bash.mjs`, помнить об этом уже не нужно.

- [ ] `npm run check` зелёный. Шаги не нумеруем — номера разъезжались по документам; полный список в шапке `scripts/pre-push-check.mjs`.
- [ ] Живой прогон по затронутым экранам + Playwright, если изменение значимое.
- [ ] `README.md` обновлён тем же коммитом, если появился новый модуль/заметная фича.
- [ ] `.env.local` с плейсхолдерами удалён перед коммитом, если создавался только для проверки.
- [ ] Если менялась схема БД — файл миграции закоммичен вместе с кодом, не отдельно потом.
- [ ] Push по уже настроенному `origin`. **Токен в URL не использовать** — он оседает в `git remote -v`, в истории шелла и в логах; хук такую команду блокирует.

## После завершения фазы/фичи

- [ ] Обновить `README.md` (таблица «Возможности»), если появился новый модуль. Таблицы статусов в `CLAUDE.md` больше нет — она устаревала быстрее, чем обновлялась.
- [ ] Обновить память Claude (файлы в `~/.claude/projects/<проект>/memory/` + строка в `MEMORY.md`) — **только фактами, которых нет в репозитории** (доступы, особенности инфраструктуры, решения). Процедуры туда не копировать: их место в skills `housepro-*`.
- [ ] Если открылся новый техдолг — не чинить на автомате: сформулировать, предложить Руслану, дождаться приоритезации (как в этой сессии).

## Красные флаги — остановиться и спросить, а не додумывать

- Память (`userMemories`) утверждает одно, а код в репозитории — другое → **доверять коду**, разошедшееся зафиксировать и сообщить.
- Задача подразумевает даунтайм или необратимое изменение схемы на живых данных → сейчас это не страшно (pre-launch), но привычку стоит выработать заранее.
- Задача пахнет процессной бюрократией «для команды» → сверить с этим файлом: команда — это два человека, бюрократия не нужна, пока не сказано обратное.
