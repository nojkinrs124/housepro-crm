Все 8 жалоб владельца воспроизведены. Главные корневые причины, которые закрывают сразу много находок:

1. **Формы теряют ввод после любой ошибки** (жалобы «данные сбросились», «собственник не подтянулся»).
   Формы на `<form action={formAction}>` + `useActionState` (16 файлов). React 19 после завершения
   action **автоматически сбрасывает неуправляемые поля формы** — и при ошибке тоже. Поля с `defaultValue`
   возвращаются к пустым дефолтам. Живьём: `/contracts/new`, залог `0` → «Укажите положительное число»,
   форма очищает собственника, арендатора, объект, сумму, залог, даты (B-02, A-01, A-10, F-05, F-07).
   Правка: возвращать введённые значения в `state` и подставлять их в `defaultValue`/`key`, либо
   перехватывать `onSubmit` + `startTransition` без авто-сброса. Делать в общем хелпере форм, не по одной.
2. **Договор без шаблона = пустой бланк.** `generateBasicDocx` в `src/features/contracts/actions/generate.actions.ts:219`
   выдаёт 24 строки: стороны, объект, сроки, сумма, подписи — ни одного пункта договора. Шаблоны в базе есть
   только у `rent_apartment` и `agency_client`; у остальных 6 типов (в т.ч. агентский с собственником,
   управление, купля-продажа) — заглушка. Плюс в заглушке «Сроки аренды» для любого типа, «(тысяч рублей)»,
   `CITY: 'г. Москва'` захардкожен (`document.service.ts:666`).
3. **У договора нет ни одного обязательного поля** — сохраняется договор без сторон, объекта, сумм, дат;
   дата окончания раньше начала принимается (B-01, B-04, A-12).
4. **График платежей не учитывает тип договора** — у агентского договора создаёт 12 начислений
   «Аренда за …» по сумме аренды (A-08).

## 4. P2 — сгруппировано по разделам (со слов агентов, кроме отмеченных)

**Сделки и стадии.** Нет отката стадии назад, клик по пройденной стадии молча игнорируется (E-08), хотя справочник
обещает откат. Отмена сделки без причины — кнопка молча ничего не делает (E-06); причина отмены нигде не видна (E-07).
Редактирование сделки с комиссией −5 молча не сохраняется (E-09). Чек-лист пишет «можно двигать дальше», а переход
блокирует статус договора (A-15). Авто-пункты «Фото загружены»/«Объявление размещено» не закрываются сами (D-05).
Пункт «Срок выхода на сделку» не имеет одноимённого поля (D-10). Создание договора по сделке не двигает сделку (C-04),
чек-лист «Договор подписан» не отмечается сам (C-05). У «Управления» пустая стадия «Поиск» (C-01).
`/deals/<номер>` вместо uuid роняет страницу (A-17, 🔎 лог `invalid input syntax for type uuid`).
Экран «Оформить» одновременно обещает и запрещает второй договор (A-04).

**Договоры и документы.** «Проверка данных для документа» ищет у агентского несуществующего «Клиента» (B-10).
Каждое сохранение создаёт пустую версию без файла (B-11). Коммерческая аренда — пустой список объектов (B-08).
Продажа — чек-лист требует дату окончания, которой нет в форме (B-09). Договор на подбор по шаблону:
пустые «___ %» вознаграждения, паспорт и реквизиты агента, «Оплата производится: ___» (D-15).

**Управление.** «Вознаграждение» = вся аренда 35 000 ₽ вместо 10 % (C-15); «Прибыль за месяц» включает деньги
собственника (C-16); акт приёма закрывается без счётчиков (C-08); вход в акт — только через иконку без подписи (C-07);
пункты про акт/показания — галочки без кнопок (C-10).

**Контакты.** Слитая карточка не говорит, куда слита (E-13). Группа дублей пропадает, если у одной карточки другое имя (E-14).

**Структура / навигация (F).** Хлебные крошки только на 2 из 14 списков (F-01); раздел «Заявки арендаторов» `/requests`
недостижим из меню (F-11); в «Настройках» две пустые карточки (F-12), три страницы настроек не слинкованы (F-13),
«Уведомления» — журнал, а не настройки (F-14); на шаблонах нет предупреждения про пустой бланк и списка переменных (F-15).
Глобальный поиск теряет результат 5 из 6 (F-16); конверсия лидов в аналитике всегда 0 % (F-08).
Ссылки фидов и подборок строятся на `NEXT_PUBLIC_SITE_URL` — на стенде `localhost` (D-13, F-17; на проде проверить env).

## 5. Предложения по UX (из жалоб владельца, не баги)

1. **Канбан:** стрелки ‹ › у краёв доски (видны при наведении), плавная прокрутка по колонке
   (`scrollBy({left: ширина колонки, behavior:'smooth'})`), автопрокрутка при наведении на край во время
   drag-and-drop, колонки уже на 1280 (сейчас видно 3 из 9).
2. **Кнопки по стадиям:** таблица «стадия → главная кнопка» в `directions.ts`. Пример для аренды «Агент»:
   Встреча → «Назначить встречу»; Договор с собственником → «Создать агентский договор»;
   Подготовка → «Загрузить фото / Опубликовать»; Показы → «Назначить показ»;
   Проверка → «Оформить договор найма»; Заселение → «Начислить комиссию»; Завершена → ничего.
   Остальные действия — в меню «…».
3. **Агентский договор:** вместо «Сформировать график платежей» — одна кнопка «Начислить вознаграждение»
   (разовая операция на сумму вознаграждения).
4. **Ошибки форм:** ошибка у конкретного поля, автоскролл к ней, ввод не теряется.

## 6. Что проверено и работает (не трогать)

Все 8 типов договоров сохраняются; редактирование одного поля не обнуляет остальные; цепочка статусов договора
и откат с подтверждением; двойной клик «Создать» не плодит договоры; повторный «Сформировать график» без дублей;
«Пересоздать график» не трогает ручные платежи; удаление договора чистит начисления и версии. Полные проходы
«Продажа» (до `sold`) и «Управление» (до «В обслуживании», цифры расчёта/отчёта совпали с SQL). Фильтры лидов
в режиме «Список», групповые действия, конвертация лида в контакт и сделку. Создание/редактирование
физлица и юрлица, объектов; запрет перескока стадий с понятным текстом; отмена с причиной и возврат в работу.
Фильтры задач и журнала бухгалтерии сходятся с SQL; импорт выписки 1С; счёт на оплату с суммой прописью;
аналитика: доход и количество объектов совпали с SQL.
