### E-01. Канбан лидов полностью игнорирует фильтры и поиск — показывает все лиды
- Приоритет: **P1** (сценарий не пройти / неверные данные на экране — прямая жалоба владельца «фильтр по новым показывает все лиды»)
- Тип: Функционал
- Где: `http://192.168.3.14:3100/leads`, режим **Канбан**, фильтры «Статус / Тип / Источник» + строка «Поиск: имя, телефон»
- Шаги:
  1. `/leads` → режим «Канбан».
  2. Клик по фильтру «Статус» → выбрать «Новый» (чип становится активным: `<button class="hp-chip active">Новый …</button>`, в localStorage `leads:filters = {"status":"new"}`).
  3. Посчитать карточки по колонкам.
  4. Повторить для «Тип: Аренда» (`{"type":"rent"}`) и «Источник: Авито» (`{"source":"avito"}`).
  5. Ввести в поиск «Лид 1».
- Ожидалось: на канбане остаётся только одна колонка «Новые» (или только карточки, подходящие под фильтр); при поиске — одна карточка.
- Фактически: **фильтр не влияет на канбан вообще**. Во всех 4 случаях отрисованы все 8 колонок со всеми 11 лидами:
  `Новые=3, Связались=1, Показ=1, Подбор=1, Заинтересованы=3, Клиенты=1, Закрыты=0, Отказ=1` (11 карточек). Нужной колонки «Новый» рядом с пустыми колонками нет — пустые колонки остаются пустыми, т.е. фильтр визуально выглядит как «ничего не произошло»/«показывает все лиды».

  SQL-эталон `new`: `new|3` — колонка «Новые» верна, лишние 8 карточек отрисованы в остальных колонках.

### E-12. «Связей: 0» у карточки, у которой есть задача; при слиянии задачи НЕ переносятся

- Приоритет: P1
- Тип: Данные
- Где: `/contacts/duplicates`, блок группы; `/contacts/<id>` после слияния
- Шаги: 1. у двух контактов-дублей (`__smoke__ E Дубль Три`, д6a68790… и 6b0e3e47…, один телефон `+7 (999) 100-77-12`) создать по задаче (`/tasks/new?contact_id=…`, «Создать задачу») → 2. открыть `/contacts/duplicates` → 3. слить пару.
- Ожидалось: счётчик «связей» учитывает задачи; после слияния задачи переезжают на оставшуюся карточку (как обещает подпись «Сделки, договоры, показы и платежи перейдут на выбранную карточку»).
- Фактически: обе карточки показывают **«связей: 0»**, хотя на каждой есть задача. После слияния задача слитой карточки **осталась указывать на неактивный дубль**: на основной карточке в блоке «ЗАДАЧИ» видна только `__smoke__ E Задача дубль A`, а `__smoke__ E Задача дубль B` пропала из работы (SQL: `contact_id` = слитый id). Причина видна в коде: список `CONTACT_REFERENCES` (`src/features/contacts/actions/duplicates.actions.ts`) содержит `deals/contracts/showings/accounting_transactions/contact_representatives/properties`, но **`tasks.contact_id` в нём нет**.

После слияния SQL: `6b0e3e47…|inactive|merged_into=d6a68790…`, но `select title,contact_id from tasks …` = `__smoke__ E Задача дубль B|6b0e3e47-4013-4c2d-bdcc-bc53bfa07048` (не перепривязана). DOM основной карточки: `ЗАДАЧИ | Задача | __smoke__ E Задача дубль A | К выполнению` (задачи B нет).
- Воспроизводимость: 1/1 (единственная пара; механизм подтверждён кодом)

### E-14. Дубли по телефону не показываются, если хотя бы у одной карточки в группе другое имя

- Приоритет: P2
- Тип: Функционал/Данные
- Где: `/contacts/duplicates`
- Шаги: 1. создать 3 контакта с одним телефоном `+7 (999) 100-77-09`: `__smoke__ E Дубль Один`, `__smoke__ E Дубль Два`, `__smoke__ E Дубль Два` → 2. открыть `/contacts/duplicates`.
- Ожидалось: как минимум пара с полностью совпадающим именем и телефоном видна как дубль.
- Фактически: группы с этим телефоном на странице **нет вообще** — из-за проверки «все имена в группе похожи» (`allSimilar` в `findDuplicateContactsAction`): одна карточка с другим именем гасит всю группу по телефону, включая очевидную пару одинаковых карточек. Контроль: пара с одинаковым именем и тем же телефоном на другом номере (`__smoke__ E Дубль Три` ×2, `+7 (999) 100-77-12`) на той же странице показывается корректно → дело именно в третьей карточке в группе.
- Доказательство: SQL — `regexp_replace(phone,'[^0-9]','','g')=79991007709` → `3` карточки; страница дублей: `3 групп, 6 карточек` и в списке только `+799…7788`, `+799…3002` и моя пара `+799…7712` — телефона `…7709` нет. Код: `duplicates.actions.ts`, функция `findDuplicateContactsAction` (строки 186–201: `const allSimilar = normalizedNames.every(...)`, `if (allSimilar && normalizedNames[0]) rawGroups.push(...)`).
- Воспроизводимость: 3/3 (проверено трижды: до/после создания третьей карточки)
