## R3. Блок «Платежи» и «Сформировать график платежей» в агентском договоре

Что видит пользователь на карточке агентского договора: блок «Платежи» со счётчиком, кнопкой «Добавить» и
кнопкой «Сформировать график платежей», ниже — «Получено 0 ₽ / Ожидается …».

1. «Добавить» → инлайн-форма «Новый платёж»: `Сумма, ₽ *`, `Срок оплаты`, `Что это` (select: **«Арендный платёж»**
   (`rent`) / **«Залог (возвратный)»** (`deposit`)), `Примечание`. Оба варианта «Что это» — про АРЕНДУ
   (платёж жильца и его залог), для агентского договора с собственником ни один не подходит: комиссия агентства

## R7. Канбан сделок `/deals` — доступность правых колонок

Канбан — один контейнер `.overflow-x-auto` (`overflow-x: auto`), внутри 9 колонок по 248 px + отступ 12 px:

| Ширина окна | clientWidth контейнера | scrollWidth | Скрыто вбок | Колонок видно целиком | Колонок задеты краем |
|---|---|---|---|---|---|
| 1280 | 956 | 2328 | 1372 px | 3 (Поиск, Встречи, Договор) | 4 |
| 1440 | 1116 | 2328 | 1212 px | 4 | 5 |
| 1920 | 1536 | 2328 | 792 px | 5 | 6 |

Колонки: ПОИСК, ВСТРЕЧИ, ДОГОВОР, ПОДГОТОВКА, ПОКАЗЫ, ПРОВЕРКА, ЗАСЕЛЕНИЕ, ЗАВЕРШЕНЫ, ОТМЕНЕНЫ — левые края 292…2372 px.

- **Кнопок-стрелок прокрутки нет.** В `main` на доске нет ни одной кнопки прокрутки
  (`[...document.querySelectorAll('main button')]` → только «Этап: все», «Направление: все», «Канбан», «Реестр»,
  вкладки направлений). Горизонтальная прокрутка — только нативный бегунок контейнера.
- **Где бегунок:** `getBoundingClientRect()` контейнера `top=415, bottom=707, height=292` при высоте окна 800/900/1080 →
  бегунок на y≈693, то есть **на самом низу области доски**, в 100–400 px от нижнего края окна.
- **При коротком окне бегунок недоступен вообще:** при высоте окна 577/600/650 px `bottom=707 > innerHeight`, при этом
  `documentElement.scrollHeight === clientHeight` (страница НЕ скроллится) и внутри `main` нет ни одного вертикального
  скроллера (`scrollHeight - clientHeight > 20` не находится ни у одного элемента) → **до горизонтального бегунка
  нельзя доскроллить**, стрелок нет. На 1280×577 при этом видны только 3 колонки из 9.
- До правых колонок при этом можно добраться лишь жестом тачпада / Shift+колесо над доской (контейнер реально
  прокручивается: `scrollWidth 2328` при `clientWidth 956`), то есть на обычной «мыши без тачпада» — только фокусом
  в контейнер и Shift+колесо; визуальной подсказки об этом в интерфейсе нет.

Источник: `a_r7_kanban.json`, `a_r7_kanban2.json`, замеры через `Emulation.setDeviceMetricsOverride` 1280/1440/1920
и 1280×577 / 1280×600 / 1366×650.

## R6. DOCX договора найма

Сформировать документ по договору найма на стенде **не удалось**: «Сформировать документ» → на карточке
**«Не удалось загрузить шаблон»** (2/2 попытки), ссылки «Скачать DOCX» не появляется, `contract_versions` не пополняется.

Причина (разбор, не подтверждено живой проверкой прод-пути):
- в `document_templates` есть строка `rent_apartment` → файл `templates/594a3056-e5b0-4afd-a85c-b980a441a82d/rent_apartment.docx`;
- политика Storage «org members read templates» разрешает чтение только если `storage.foldername(name)[2]` = `organization_members.user_id`;
- в пути стоит **id организации** (`594a3056-e5b0-4afd-a85c-b980a441a82d`), а участников с таким `user_id` — **0**
  (`select count(*) from organization_members where user_id='594a3056…'` → 0; участники — `e1de9ce6…`, `04dcac1f…`);
- код приложения (`generateContractDocx`, `generate.actions.ts:40-56`) читает шаблон **пользовательским** клиентом (RLS),
  админский путь (`supabaseAdmin`, строки 140-212) вызывается только из Telegram-бота. Поэтому чтение шаблона отклоняется.
- сам файл в бакете есть: `GET /storage/v1/object/document-templates/templates/594a3056…/rent_apartment.docx` с service key → 200, 17 145 байт.

Скорее всего это артефакт подготовки стенда (загрузка шаблонов положила в путь id организации вместо id пользователя-загрузчика,
хотя собственный код загрузки в `/settings/templates` использует `templates/${user.id}/`). Для проверки R6 живьём стенд нужно поправить.

Что удалось установить по шаблону и по заглушке (файл шаблона разобран `docx_dump.mjs`):
- шаблон найма: 158 абзацев, Times New Roman **12 pt**, выравнивание по ширине (`both`), `w:line=240` (одинарный),
  **отступов первой строки нет** (`ind:-`); 45 плейсхолдеров вида `{{ФИО_АРЕНДОДАТЕЛЯ}}`, `{{КОЛ-ВО_ДЕТЕЙ}}`, `{{ЖИВОТНЫЕ_ЗАПРЕЩ_РАЗРЕШ}}` и т.д.
- все 45 плейсхолдеров шаблона имеют соответствие в `ContractVariables` (проверено сопоставлением: `document.service.ts:8-141` содержит
  все ключи, включая `'КОЛ-ВО_ДЕТЕЙ'`, `'ЖИВОТНЫЕ_КОЛ-ВО'`, `'СЧЕТЧИК_ЭЛК-ВО'`); незаполненные значения docxtemplater подставляет
  строкой `'___'` (`nullGetter: () => '___'`), у части полей есть дефолты («0», «2»).
- сгенерированный DOCX **агентского** договора (шаблона для `agency_owner` нет) — встроенная заглушка:
  без `styles.xml` и без `sectPr` (не заданы шрифт, кегль, поля страницы, абзацные отступы), см. A-06.
