## Что сделано

### Страховочная сетка (фаза 0)

- Локальный Supabase в Docker (`supabase/config.toml`), 49 миграций накатываются
  на чистую базу, схема сверена с продом по хэшам.
- По дороге выяснилось и починено: baseline-снапшот не накатывался на пустую базу
  (проверки констрейнтов без схемы, потерянные `ON DELETE` у 66 FK), 46 файлов
  миграций имели одинаковые версии, **21 миграция прода за 20.07–31.08 отсутствовала
  в репозитории** — восстановлена gap-миграцией `20260831235959` по
  `information_schema` прода.
- Смоук на 7 потоков (`npm run test:smoke`) — вход/выход, контакт, сделка,
  канбан, задача, генерация DOCX, платёж — проверяет записи в базе, ходит только в
  изолированный Supabase (предохранитель от прода в `e2e/seed.ts`), записи с
  префиксом `__smoke__` подчищаются.
- Production-сборка локально: `node scripts/e2e/prod-local.mjs`.

## Что не сделано

- **A4/A5 (Stripe):** комментарий в `env.ts` и плейсхолдеры в `ci.yml` — не
  правил, чтобы не трогать CI без нужды; безопасно снять отдельным коммитом.
- **B4 (схема):** миграцию `DROP COLUMN` для легаси-колонок не готовил —
  `guard-migration` блокирует DROP, решение было «оставить в схеме и вычистить из
  кода»; из кода фолбэки убраны (A2, A3).
- **B2.4:** «Уведомления» и «Почта» не объединены в одну страницу — обе остались,
  разнесены по группам «Аккаунт» / «Интеграции».
- **Форма договора:** поля типа договора и тарифа остаются на виду (7–9 полей у
  части типов) — они нужны документу, прятать их в «Дополнительно» значило бы
  ловить браузерную валидацию на скрытом поле. Осознанное исключение из правила 3.
- **Юрлицо в форме контакта:** 7 полей на виду (ИНН обязателен по схеме).
- **`loading.tsx`** для 11 модулей (C0.8) — не делал, общий скелетон остался.
- **Онбординг** — не смотрел: аудит по нему находок не дал.
- **`docs/handbook`** обновлён по 9 главам, но в базу знаний на проде
  (`npm run seed:handbook`) не пересеян — это запись в прод, делается при выкате.
- Warning `The requested resource isn't a valid image for /site/ruslan.jpg` при
  локальном `next start` — особенность локального запуска (оптимизатор идёт через
  middleware), на Vercel статику отдаёт CDN. Не чинил.
