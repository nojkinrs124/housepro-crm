Выкатить текущие изменения в прод. Аргументы: `$ARGUMENTS`.

Процедура — в skill `housepro-release`, она остаётся единственным источником правды.
Команда её не заменяет: она задаёт порядок шагов и не даёт забыть то, на чём
выкат спотыкался раньше. Прочитай skill, если в этой сессии его ещё не читал.

## Порядок

**1. Осмотреть, что выкатывается.** `git status --short` и `git diff --stat`.
Нечего коммитить — так и сказать, дальше не идти.

**2. Поднять версию — ДО проверки, не после.**

Тип берётся из первого аргумента (`patch` / `minor` / `major`). Аргумента нет —
определить по диффу самостоятельно: починка поведения → `patch`, новая
возможность → `minor`, ломающее изменение → `major`.

```bash
npm run version:patch
```

Порядок здесь важнее, чем кажется. `package.json` входит в отпечаток
`npm run check` (`scripts/checks/stamp.mjs`, список `ROOT_FILES`), поэтому бамп
версии после зелёной проверки делает отпечаток несовпадающим — и `guard-bash`
блокирует пуш, требуя прогнать проверку заново. Сначала версия, потом проверка.

**3. Прогнать проверку.**

```bash
npm run check
```

Запускать в фоне и докладывать промежуточный статус — прогон идёт минуты, тишина
читается как зависание. Любой красный шаг = выкат останавливается, чинить и
прогонять заново. Проверка сама пишет отпечаток при успехе.

**4. Дописать то, что идёт тем же коммитом.**

- `README.md` — если появился новый модуль или заметная фича (меняется ответ на
  вопрос «что умеет система»). Для багфиксов не нужно.
- `docs/handbook/` — если поведение экрана разошлось с инструкцией. После правки
  главы пересеять: `npm run seed:handbook`.
- Файл миграции в `supabase/migrations/` — если менялась схема, вместе с кодом.
- `.env.local` с плейсхолдерами — удалить, если создавал для проверки.

Правил код на этом шаге — вернуться к шагу 3, отпечаток уже не тот.

**5. Коммит и пуш.**

Сообщение — из второго аргумента, иначе составить по диффу. Формат:
`тип(модуль): краткое описание` + детали списком. Тип: `feat` / `fix` / `docs` /
`refactor`. Описание — что изменилось для человека, а не какие файлы тронуты.

```bash
git add -A
git commit -m "fix(management): описание"
git push origin main
```

Токен в URL не использовать — пуш по настроенному `origin`, PAT в командной
строке хук блокирует.

**6. Отчитаться.** Версия, тип бампа, что вошло в коммит, ссылка на прод
https://housepro24.vercel.app. Если деплой не появился вовсе — первым делом
`vercel.json` и кроны, разбор в skill `housepro-release`.
