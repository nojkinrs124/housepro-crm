# Выкат HousePro CRM

Порядок ниже собран из трёх разных источников, которые раньше противоречили друг другу
(CLAUDE.md в двух местах, docs/WORKFLOW.md и память). Это единственная актуальная версия.

## 1. Обязательная проверка

```bash
npm run check
```

Гоняет семь шагов: `tsc --noEmit` → event handlers в Server Components → границы
client/server → визуальный стандарт «Кабинет» → кроны в `vercel.json` → `npm run build`
→ `npm test`. Любой красный шаг = пуш запрещён.

При успехе скрипт пишет отпечаток кода в `.claude/.check-stamp.json`. Хук
`.claude/hooks/guard-bash.mjs` пропускает `git push`, только если отпечаток совпадает
с текущим содержимым `src/`, `scripts/` и корневых конфигов. Правил код после
проверки — прогнать заново, отпечаток уже не тот.

**Почему одного `tsc`/`build` мало:** страницы с `export const dynamic = 'force-dynamic'`
или с `cookies()` Next помечает как `ƒ Dynamic` и их тело во время сборки не выполняет.
Ошибка «функция из клиентского компонента вызвана на сервере» проходит мимо `tsc` и
мимо `build` и всплывает только в реальном запросе в проде — так и появился этот скрипт.

## 2. Живой прогон (для значимых изменений)

`npm run check` не заменяет живую проверку. Поднять приложение и пройти по затронутым
экранам, прокликать формы.

```bash
npx playwright test                                      # по проду
E2E_BASE_URL=http://localhost:3000 npx playwright test --workers=1   # локально
```

- Доступы — в `.env.e2e` в корне (под `.gitignore`). `playwright.config.ts` читает файл
  сам, тянуть его через шелл не нужно, секреты в командной строке не светить.
- Локально **только `--workers=1`**: с двумя воркерами рядом с дев-сервером процесс
  убивают по памяти (exit 137). Полный прогон ~1–1.2 минуты.
- Набор `e2e/new-features-smoke.spec.ts` (19 тестов) проходит по новым экранам.
- Падения разбирать до конца, отделяя настоящие баги от неточных селекторов.

## 3. Что обновить перед коммитом

- **`README.md`** — если появился новый модуль или заметная фича (меняется ответ на
  вопрос «что умеет система»): таблица «Возможности» и вступление, **тем же коммитом**.
  Для мелких багфиксов не нужно. Hook `stop-readme.mjs` напомнит, если забыл.
- **Версия** в `package.json` — при любых правках `src/` или миграций, тем же
  коммитом: `npm run version:patch` (фикс) / `version:minor` (фича) /
  `version:major` (ломающее). Она видна в футере настроек, по ней понимают, что
  раскатано в проде. Без бампа `guard-bash` не пустит пуш.
- **Файл миграции** в `supabase/migrations/` — если менялась схема, вместе с кодом,
  не отдельным пушем потом.
- **`.env.local`** с плейсхолдерами — удалить, если создавал только для проверки.

## 4. Коммит и пуш

```
feat(module): краткое описание

- детали что сделано
- Build: verified locally, 0 errors
```

```bash
git add -A
git commit -m "feat(module): описание"
git push origin main
```

**Токен в URL не использовать** — пуш по уже настроенному `origin`. PAT в
`git remote set-url` оседает в `git remote -v`, в истории шелла и в логах;
хук такую команду блокирует.

## 5. После пуша

- **Деплой не появился вовсе** (ни успешного, ни упавшего в списке Vercel, журнал
  активности пуст, CI на GitHub зелёный) → первым делом проверить `vercel.json`.
  Тариф Hobby разрешает крон не чаще раза в сутки; более частое выражение Vercel
  отвергает при валидации и **молча отбрасывает весь деплой**. Текст ошибки виден
  только вручную: Vercel → Deployments → «…» → Create Deployment → выбрать ветку.
  Всё, что нужно чаще суток, живёт в GitHub Actions (`channel-heartbeat.yml`,
  `avito-messenger.yml`). Это же проверяет шаг «vercel.json — кроны» в `npm run check`.
- Прод — **https://housepro24.vercel.app** (не `housepro.vercel.app`, тот занят чужим
  приложением).
- CI на GitHub гоняет тот же `npm run check` — но «зелёный CI на странице PR» уже
  однажды расходился с реальностью (Dependabot PR #6 сломал весь тестовый набор при
  зелёном CI). После мержа чужих PR перепроверять локально.

## Не молчать

Длинные команды запускать в фоне и докладывать промежуточный статус. Тишина на
несколько минут читается как зависание, даже когда работа идёт.
