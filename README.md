## Что это

**HousePro CRM** — многопользовательская (multi-tenant) система для риелторских агентств: ведение лидов и сделок, объекты недвижимости, договоры с автогенерацией DOCX, платежи, аналитика, показы объектов, публичные подборки для клиентов и Telegram-бот для быстрых операций с телефона.

Проект построен как многоарендная система: организации изолированы через Row Level Security на уровне базы данных, есть онбординг новых агентств и публичный REST API для интеграций. Подписки на саму CRM нет — её сделают заново, когда дойдёт до масштабирования.

У собственников и арендаторов объектов в управлении есть личные кабинеты на сайте: собственник видит отчёты и сальдо, арендатор — свои платежи, передаёт показания счётчиков и вызывает мастера. Вход общий с CRM — на `/login` человек сначала выбирает, кто он: сотрудник входит по email и паролю, собственник или арендатор по телефону с одноразовым кодом, и лишних полей не видит ни тот, ни другой (выбор запоминается в браузере); данные каждый раз проверяются по выданному доступу, и его отзыв закрывает кабинет немедленно.

Работа агентства разделена на четыре направления, и у каждого своя воронка: аренда по тарифу «Агент», управление объектом, продажа и покупка, подбор объекта для арендатора. Стадии отражают реальный порядок шагов — например, при подборе для арендатора договор на услуги подписывается **до** начала поиска, и система не даст перейти к вариантам раньше.

Работа сама двигается по воронке вслед за реальными действиями: договор создан из карточки → стадия договора своего направления; DOCX сформирован → следующий шаг; платёж отмечен оплаченным → закрытие. Перейти на стадию, к которой ещё не готовы, нельзя: система называет, чего именно не хватает — незакрытых пунктов чек-листа или неподписанного договора. Интерфейс поддерживает светлую и тёмную тему.

## ✨ Возможности

| Модуль | Что умеет |
|---|---|
| 🧲 **Лиды** | Kanban-доска, воронка, конвертация в контакт с ролью по типу обращения («сдать/продать» — собственник), защита от дублей по телефону, связь лид ↔ контакт на обеих карточках, задачи и показы прямо с карточки |
| 🧭 **Направления** | Четыре процесса агентства со своими воронками: аренда «Агент», управление, продажа, подбор для арендатора. Чек-лист на каждой стадии, предусловия перехода и внятная причина отказа вместо «ошибки валидации» |
| 💼 **Тарифы агентства** | Справочник условий работы: разовый процент от сделки, ежемесячный процент от платежа, фиксированная выплата собственнику, фикс, договорная. Ставка фиксируется в договоре при подписании и не меняется задним числом. Правило «первая сделка с собственником бесплатно» |
| 🤝 **Сделки** | Kanban по направлениям, тариф прямо в сделке, кнопка «Оформить» — договор по стадии (агентский до договора, итоговый после), график начислений, задача на подписание, статус объекта и расчёт комиссии по тарифу одним подтверждением. На карточке — договоры, показы, подборки и файлы; чек-листы закрываются сами по фактам (показ проведён, объект опубликован, фото загружены); отмена — только с причиной |
| 👤 **Контакты** | Единая карточка клиента/собственника, физлица и юрлица с реквизитами |
| 🏢 **Объекты** | Каталог недвижимости, фото (прямая загрузка в Yandex Object Storage по несколько сразу, порядок публикации перетаскиванием), показы. Кнопка «Сгенерировать объявление» в карточке: сырые заметки агента + заполненные поля объекта → готовый текст для Авито через OpenRouter, стримом, с превью того, что уходит в промпт. Модель не додумывает: пустые поля в промпт не попадают, инфраструктура и цифры — только из вводных. «Вставить» пишет текст прямо в «Описание» объекта — оно и уходит в фиды площадок; `listing_*` хранят заголовок, вводные и модель последней генерации |
| 📁 **Подборки** | Собираются под сделку подбора или лида; публичная ссылка открывается без входа в CRM; отправка клиенту закрывает стадию «Подборка отправлена» |
| 📄 **Договоры** | Автогенерация DOCX по шаблонам (юрлицо подставляется реквизитами организации), история версий с восстановлением; подпись договора двигает сделку, сформированный файл — ещё нет |
| 📚 **Бухгалтерия** | Доходы/расходы с системными категориями из коробки, «Провести» одной кнопкой с датой проведения, повторяющиеся операции, P&L по месяцам, платежи по договорам, счёт с реквизитами и плательщиком; касса и доход агентства — отдельные цифры (транзитные платежи клиентов и депозиты не попадают в доход агентства ни здесь, ни в Аналитике); срез по направлению работы, сотруднику и объекту режет статистику, графики и список операций разом |
| ✅ **Задачи** | Kanban-доска задач с дедлайнами |
| 👥 **Сотрудники** | Приглашение по email, роли (admin/manager/agent/accountant), KPI-статистика |
| 📊 **Аналитика** | Воронка, конверсия, платежи — с произвольным периодом (Recharts); срез по направлению/сотруднику/объекту и сравнение с предыдущим периодом на ключевых показателях |
| 🏘 **Показы** | Планирование показов объектов, фиксация результата |
| 🔍 **Поиск** | Глобальный поиск по всей системе (Ctrl+K) |
| 📤 **Экспорт** | XML для Avito/CIAN, CSV для 1С |
| 🤖 **Telegram-бот** | «Занести в CRM» по документам: выбираешь арендатор / собственник / объект / договор, присылаешь фото паспорта, выписку ЕГРН, договор и телефон — бот показывает всё, что прочитал, и после «Создать» заводит контакт, лид, объект и сделку связанными, сканы кладёт в карточку. Дубли ловит по телефону, паспорту и кадастровому номеру. Плюс диалог: сделки, задачи, операции, голосовые заметки, фото чека → расход. Две роли: владелец и сотрудник |
| 🔌 **API** | Публичный REST API `/api/v1` с ключами, лимитом 120 запросов в минуту на организацию и HMAC-подписанными вебхуками |
| 🛡 **Аудит** | Журнал всех изменений по организации |
| 📞 **Коммуникации** | Единая лента общения: звонки из АТС, WhatsApp, письма, заметки |
| ✉️ **Почта** | Договоры, напоминания об оплате, подборки и приглашения на показ — письмом клиенту |
| 🗓 **Календарь** | Общий календарь агентства: показы, дедлайны задач и плановые платежи; подписка в Google/Яндекс/Apple по ссылке |
| 🧾 **Сверка** | Ссылки на онлайн-оплату (ЮKassa) и импорт банковской выписки 1С |
| ✍️ **Подпись** | Простая электронная подпись договора по ссылке с кодом из письма |
| 🖋 **Подпислон** | Отправка договора на подпись через оператора ПЭП: код в СМС, согласия на ПЭП и обработку ПД подшиваются в файл автоматически |
| 📥 **Импорт** | Перенос базы контактов, объектов и лидов из Excel/CSV |
| 🧹 **Дубли** | Поиск и слияние дублей контактов по телефону и почте |
| 🏛 **Управление** | Объекты в доверительном управлении: договор, арендатор и общение с ним, график начислений, платежи, счётчики, задачи и печатный отчёт собственнику. Три схемы расчёта с собственником на выбор — процент от платежа, фиксированная выплата с оставлением разницы агентству или фиксированная выплата, ограниченная фактическими поступлениями; от схемы зависит, кто несёт риск простоя объекта |
| 📚 **База знаний** | Инструкции для сотрудников внутри CRM: стандартный справочник по всем разделам загружается одной кнопкой; рубрики, поиск, markdown с предпросмотром, черновики, срок годности статьи с отметкой «проверено» |
| 🗂 **Реестры** | Единый вид всех списков: поиск, фильтры-чипы, выделение строк и групповые действия — смена статуса, назначение ответственного, удаление |
| 🌐 **Сайт «Услуги»** | Раздел для собственников на публичном сайте: хаб `/uslugi` и страницы «Сдать квартиру» (калькулятор дохода по трём тарифам, гарантия платежа, сравнение, документы, «Что если»), «Снять квартиру», «Продать или купить». Все числа — в одном конфиге `src/features/site/uslugi/config.ts`; заявка уносит в лид тариф, район, комнатность, ставку и расчёт, у каждой страницы свой источник для конверсии. Страница «О компании» — основатель, живые цифры из CRM (квартир в управлении, закрытых сделок через `public_site_stats()`), реквизиты и FAQ подстраиваются под форму собственности из настроек. Незакрытые вопросы — `docs/uslugi/OPEN-QUESTIONS.md` |
| 🔑 **Кабинет собственника** | Свои объекты на сайте: текущий арендатор и срок, месячные отчёты с расшифровкой, сальдо, показания счётчиков. Вход на общей странице `/login`: дверь «Я собственник или арендатор», дальше телефон и одноразовый код, без пароля |
| 🧰 **Кабинет арендатора** | Свои платежи и сроки, передача показаний счётчиков, заявки на клининг, сантехника, электрика — со статусом до выполнения |
| 🛠 **Заявки** | Обращения жильцов в общем потоке работы: заявка сразу становится задачей ответственному, а расход по ней попадает в отчёт собственнику |
| 📎 **Файлы** | Сканы паспортов, документы на объект и по сделке — в приватном хранилище с доступом только своей организации, скачивание по временной ссылке |
| 🧯 **Чего не хватает** | Блок в карточке объекта, контакта, лида, договора и операции: какая функция молча не сработает из-за пустого поля — объявление не уйдёт на площадки, напоминание не отправится, в договоре останется пропуск. Заводить записи можно в любом порядке, быстрое создание связанных карточек — прямо из формы |

## 🧱 Технологический стек

- **Frontend:** Next.js 16 (App Router) · React 19 · TypeScript · Tailwind CSS v4 (свои компоненты, без библиотеки UI)
- **Backend:** Supabase (PostgreSQL + Auth + Storage), Row Level Security на уровне организации
- **Фото объектов:** Yandex Object Storage (S3, серверы в РФ) через `src/lib/storage/photo-storage.ts`;
  переключатель `STORAGE_DRIVER` возвращает на Supabase Storage без правок кода
- **Оплата:** ЮKassa — платежи клиентов агентства
- **Интеграции:** DaData (адреса и реквизиты), Яндекс.Карты, телефония (Манго/UIS/Zadarma),
  WhatsApp (Wazzup/Green API), Авито-мессенджер, фиды Авито/ЦИАН/Яндекс/Домклик
- **Документы:** docxtemplater + pizzip (генерация DOCX по шаблонам)
- **Аналитика/графики:** Recharts
- **UX:** Framer Motion, sonner (toasts), нативный HTML5 drag-and-drop (Kanban), нативный `<dialog>` (модалки)
- **Качество:** Vitest, Sentry, GitHub Actions CI
- **Деплой:** Vercel

## 🚀 Быстрый старт

```bash
git clone https://github.com/nojkinrs124/housepro-crm.git
cd housepro-crm

# зависимости (обязательно с этим флагом)
npm install --legacy-peer-deps

# переменные окружения
cp .env.local.example .env.local
# заполни NEXT_PUBLIC_SUPABASE_URL и NEXT_PUBLIC_SUPABASE_ANON_KEY
# из Supabase Dashboard → Project Settings → API

npm run dev
```

Приложение будет доступно на [http://localhost:3000](http://localhost:3000).

### Проверка перед коммитом

```bash
npm run check
```

Прогоняет по цепочке: проверку типов → сканер event-хендлеров в Server Components → анализ границы client/server (импорты клиентских функций на сервере и функции-пропы, уходящие в клиентские компоненты) → правила серверного слоя → поля форм, которые обработчик не читает → визуальный стандарт → частоту кронов → сборку → тесты. Тот же скрипт выполняется в CI при каждом push/PR.

## ☁️ Деплой

1. Импортируй репозиторий на [vercel.com](https://vercel.com)
2. Добавь переменные окружения в настройках проекта:
   - `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY`
   - `SUPABASE_SERVICE_ROLE_KEY` (только на сервере)
   - `UPSTASH_REDIS_REST_URL`, `UPSTASH_REDIS_REST_TOKEN` (rate limiting)
   - `RESEND_API_KEY` или `UNISENDER_API_KEY` + `EMAIL_FROM` (почта клиентам)
   - `DADATA_API_KEY` (подсказки адресов и реквизитов, координаты объектов)
   - `NEXT_PUBLIC_YANDEX_MAPS_KEY` (карты в подборках и на карточке объекта)
   - `OPENROUTER_API_KEY` (Telegram-бот, посты канала, генератор объявлений); `OPENROUTER_LISTING_MODEL` — опционально, отдельная модель для объявлений (по умолчанию `OPENROUTER_MODEL`, затем `anthropic/claude-sonnet-5`)
   - `CRON_SECRET` (задачи по расписанию из `vercel.json`)
3. Deploy

Подключение телефонии, WhatsApp и приёма платежей делается не через переменные
окружения, а в интерфейсе — у каждого агентства свои учётные данные.
Полное руководство по всем интеграциям — [`docs/INTEGRATIONS.md`](./docs/INTEGRATIONS.md).

## 📁 Структура проекта

```
src/
  app/
    (auth)/          # страницы авторизации
    (dashboard)/      # основные разделы CRM
    api/v1/           # публичный REST API
  components/         # переиспользуемые UI-компоненты
  features/           # бизнес-логика по модулям (actions, components, services)
  lib/                # supabase-клиенты, права доступа, rate limiting, аудит
  types/               # общие TypeScript-типы
supabase/
  migrations/          # история миграций БД
  functions/            # Edge Functions (в т.ч. Telegram-бот)
```

Как работать в системе (для сотрудников агентства) — справочник по разделам в
[`docs/handbook/`](./docs/handbook/README.md).

Полное руководство по паттернам и правилам разработки — в [`CLAUDE.md`](./CLAUDE.md),
по подключению внешних сервисов — в [`docs/INTEGRATIONS.md`](./docs/INTEGRATIONS.md).
